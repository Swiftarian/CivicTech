## 系統概述

## 完整測試流程

本測試流程涵蓋從管理員建立送餐任務、指派義工、義工執行送餐、到收餐人確認收餐的完整過程。

### 階段一：管理員建立送餐任務

管理員需要先建立送餐任務，並指定收餐人資訊、送餐地址、配送時段等詳細資料。

#### 步驟1.1：管理員登入系統

管理員可以使用以下兩種方式登入系統。

**方式A：使用Manus OAuth登入（推薦EDDIE使用）**

1. 訪問首頁：https://3000-izgcpau02zu6e0px8ui4s-4b73773b.manus-asia.computer
2. 點擊右上角「登入」按鈕
3. 使用Manus OAuth登入（huanchenlin@gmail.com）
4. 登入成功後，點擊導航列的「管理後台」連結

**方式B：使用測試登入頁面（推薦jacky和chelsea使用）**

1. 訪問測試登入頁面：https://3000-izgcpau02zu6e0px8ui4s-4b73773b.manus-asia.computer/test-login
2. 輸入Email：jacky.hsieh@insight.ntu.edu.tw
3. 輸入密碼：SecurityTest2024!
4. 點擊「登入」按鈕
5. 登入成功後，手動訪問管理後台：https://3000-izgcpau02zu6e0px8ui4s-4b73773b.manus-asia.computer/admin

#### 步驟1.2：進入送餐服務管理頁面

管理員登入後台後，可以看到多個管理標籤頁。

1. 在管理後台頁面，點擊「送餐服務」標籤
2. 系統顯示送餐任務列表和統計資訊
3. 點擊「建立送餐任務」按鈕

#### 步驟1.3：填寫送餐任務資料

系統會顯示建立送餐任務的表單，管理員需要填寫以下資訊。

**必填欄位**：

- **收餐人姓名**：例如「王小明」
- **收餐人電話**：例如「0912345678」
- **送餐地址**：例如「台東市更生北路616巷9號」
- **配送日期**：選擇送餐日期
- **配送時段**：選擇上午或下午時段

**選填欄位**：

- **特殊需求**：例如「素食」、「需要餐具」等備註

填寫完成後，點擊「建立任務」按鈕。系統會自動產生以下資訊：

- **送餐編號**：例如「MD1765084000123」
- **驗證碼**：6位英數字混合，例如「A3B7C9」
- **QR Code**：供收餐人掃描確認的專屬QR Code
- **確認連結**：供收餐人點擊確認的網址

#### 步驟1.4：系統自動發送通知

送餐任務建立成功後，系統會自動執行以下動作。

**LINE通知（優先）**：

如果收餐人已綁定LINE帳號，系統會透過LINE Messaging API發送通知訊息，內容包含：

- 送餐編號
- 驗證碼
- 預計送達時間
- 確認收餐連結

**SMS簡訊通知（備援）**：

如果收餐人未綁定LINE，系統會自動降級使用SMS簡訊發送通知（目前為模擬模式，實際部署時需整合Twilio等SMS服務）。

### 階段二：管理員指派義工

送餐任務建立後，管理員需要將任務指派給特定的義工執行。

#### 步驟2.1：選擇送餐任務

在送餐服務管理頁面的任務列表中，找到剛才建立的送餐任務。任務狀態應顯示為「待指派」。

#### 步驟2.2：指派義工

1. 點擊任務列表中的「指派義工」按鈕
2. 系統顯示可用義工列表
3. 選擇義工（例如：vol1）
4. 點擊「確認指派」按鈕

#### 步驟2.3：系統發送義工通知

指派成功後，系統會自動執行以下動作。

**LINE通知義工（如果義工已綁定LINE）**：

系統會透過LINE發送任務指派通知給義工，內容包含：

- 送餐編號
- 收餐人姓名
- 送餐地址
- 配送日期和時段

**任務狀態更新**：

任務狀態從「待指派」更新為「已指派」，義工可以在其專屬介面中看到此任務。

### 階段三：義工確認班表並準備送餐

義工收到任務指派通知後，需要登入系統確認班表和任務詳情。

#### 步驟3.1：義工登入系統

1. 訪問測試登入頁面：https://3000-izgcpau02zu6e0px8ui4s-4b73773b.manus-asia.computer/test-login
2. 輸入Email：vol1@taitung.gov.tw
3. 輸入密碼：Volunteer2024!
4. 點擊「登入」按鈕
5. 登入成功後，手動訪問管理後台：https://3000-izgcpau02zu6e0px8ui4s-4b73773b.manus-asia.computer/admin

#### 步驟3.2：查看指派的送餐任務

義工登入後台後，可以看到專屬的義工功能標籤頁。

1. 點擊「志工送餐」標籤
2. 系統顯示指派給該義工的所有送餐任務
3. 義工可以使用篩選功能：
   - **日期篩選**：所有日期 / 今日 / 本週
   - **狀態篩選**：所有狀態 / 待配送 / 配送中 / 已送達

#### 步驟3.3：確認任務詳情

在任務列表中，義工可以看到以下資訊：

- **送餐編號**：例如「MD1765084000123」
- **收餐人姓名**：例如「王小明」
- **送餐地址**：例如「台東市更生北路616巷9號」
- **收餐人電話**：例如「0912345678」
- **配送時段**：例如「上午 09:00-12:00」
- **任務狀態**：例如「待配送」

### 階段四：義工開始送餐

義工確認任務詳情後，可以開始執行送餐任務。

#### 步驟4.1：開始配送

1. 在任務列表中，找到要執行的送餐任務
2. 點擊「開始配送」按鈕
3. 系統將任務狀態更新為「配送中」

**注意**：目前GPS追蹤功能已暫時關閉，方便在非台東地區測試。實際部署時，系統會每30秒自動上傳義工的GPS位置，管理員可以在即時地圖追蹤頁面查看義工的當前位置和路徑軌跡。

#### 步驟4.2：使用導航功能

系統提供一鍵導航功能，方便義工快速前往送餐地址。

1. 在任務詳情中，點擊「導航」按鈕
2. 系統自動開啟Google Maps導航
3. 導航目的地自動設定為送餐地址

#### 步驟4.3：聯絡收餐人

如果需要聯絡收餐人，系統提供一鍵撥號功能。

1. 在任務詳情中，點擊「撥號」按鈕
2. 系統自動撥打收餐人電話（在手機上使用）

### 階段五：收餐人確認收餐

義工送達後，收餐人需要確認收餐。系統提供兩種確認方式。

#### 方式A：掃描QR Code確認（推薦）

1. 義工點擊「顯示收餐QR Code」按鈕
2. 系統顯示QR Code對話框
3. 收餐人使用手機掃描QR Code
4. 系統自動跳轉到收餐確認頁面
5. 收餐人輸入驗證碼（義工會告知）
6. 點擊「確認收餐」按鈕

#### 方式B：手動輸入驗證碼確認

1. 收餐人訪問收餐確認頁面：https://3000-izgcpau02zu6e0px8ui4s-4b73773b.manus-asia.computer/meal-confirm
2. 輸入6位驗證碼（義工會告知，例如「A3B7C9」）
3. 點擊「確認收餐」按鈕

#### 方式C：透過LINE連結確認

1. 收餐人打開LINE收到的送餐通知訊息
2. 點擊訊息中的「確認收餐」連結
3. 系統自動跳轉到收餐確認頁面
4. 輸入驗證碼
5. 點擊「確認收餐」按鈕

#### 確認成功

收餐確認成功後，系統會顯示以下資訊：

- 送餐編號
- 送餐義工姓名
- 確認時間
- 感謝訊息

同時，系統會自動更新送餐任務狀態為「已送達」。

### 階段六：義工完成送餐

收餐人確認收餐後，義工可以在系統中標記任務完成。

#### 步驟6.1：完成送餐

1. 在任務詳情中，點擊「完成送餐」按鈕
2. 系統確認收餐人已確認收餐
3. 任務狀態更新為「已完成」

#### 步驟6.2：查看送餐記錄

義工可以在「志工送餐」標籤中查看所有已完成的送餐記錄，包含：

- 送餐日期和時間
- 收餐人資訊
- 完成狀態

## 常見問題

### Q1：義工登入後看不到送餐任務？

**可能原因**：

1. 義工帳號沒有對應的志工記錄
2. 送餐任務沒有指派給該義工
3. 義工帳號的role設定錯誤

**解決方法**：

1. 請管理員在「志工管理」標籤中確認義工記錄是否存在
2. 請管理員在「送餐服務」標籤中確認任務是否已指派給該義工
3. 請管理員檢查義工帳號的role是否設定為'volunteer'

### Q2：收餐人輸入驗證碼後顯示錯誤？

**可能原因**：

1. 驗證碼輸入錯誤（區分大小寫）
2. 送餐任務已經確認過
3. 送餐任務不存在

**解決方法**：

1. 請義工再次確認驗證碼（6位英數字混合）
2. 請義工在系統中檢查任務狀態
3. 請管理員在後台確認任務是否存在

### Q3：GPS追蹤功能無法使用？

**說明**：

目前GPS追蹤功能已暫時關閉，方便在非台東地區測試。實際部署時，系統會要求義工開啟定位權限，並每30秒自動上傳GPS位置。

### Q4：LINE通知沒有收到？

**可能原因**：

1. 收餐人或義工沒有綁定LINE帳號
2. LINE Bot設定錯誤
3. LINE Channel Access Token過期

**解決方法**：

1. 請收餐人或義工先加入LINE Bot好友
2. 請管理員在收餐人管理頁面確認LINE綁定狀態
3. 請系統管理員檢查LINE環境變數設定
